ES-NL2DSL: A COMPREHENSIVE FRAMEWORK FOR SECURE NATURAL LANGUAGE TO ELASTICSEARCH DSL TRANSLATION IN CYBERSECURITY CONTEXTS

Abstract

This document presents a comprehensive analysis of ES-NL2DSL (Elasticsearch Natural Language to Domain Specific Language), a sophisticated framework designed to bridge the semantic gap between human-readable security analysis queries and machine-executable Elasticsearch queries. The system addresses the critical challenge of enabling security analysts with varying technical expertise to interact effectively with large-scale cybersecurity log repositories without requiring deep knowledge of Elasticsearch query syntax.

1. SYSTEM PURPOSE AND FUNCTIONALITY

ES-NL2DSL serves as an intelligent translation layer that converts natural language queries into validated, secure, and optimized Elasticsearch Domain Specific Language (DSL) queries. The system specifically targets cybersecurity log analysis applications, where analysts need to investigate network traffic patterns, identify potential security incidents, and perform forensic analysis across massive datasets. The framework supports both synthetic evaluation datasets and real-world network traffic data from the CIC-IDS2017 cybersecurity benchmark, encompassing over 2.8 million network flow records with labeled attack patterns.

The primary objectives of the system are threefold: (1) to democratize access to complex log analysis capabilities by removing the barrier of DSL expertise, (2) to enforce security and operational constraints that prevent both malicious query injection and resource exhaustion, and (3) to provide quantifiable evaluation metrics that ensure translation accuracy and retrieval effectiveness. The system achieves these objectives through a multi-layered architecture that combines large language model (LLM) capabilities with deterministic validation rules and sophisticated security filters.

2. ARCHITECTURE AND METHODOLOGIES

The system employs a modular, pipeline-based architecture that separates concerns across distinct processing stages. At its core, the framework implements three complementary query generation methodologies: constrained generation, rule-based translation, and zero-shot LLM generation. The constrained generation approach represents the primary methodology, utilizing few-shot prompting with schema-aware context injection to guide LLMs toward producing syntactically and semantically valid queries. This approach incorporates field catalogs, operator constraints, and temporal normalization to ensure generated queries conform to the target Elasticsearch schema.

The architecture implements a sophisticated validation pipeline that enforces multiple levels of constraints. Time window validation ensures queries specify bounded temporal ranges (maximum 7 days by default) to prevent unbounded searches that could impact system performance. Field validation restricts queries to a whitelist of approved fields, preventing information leakage through unauthorized field access. Cost-based validation estimates query execution overhead and rejects queries exceeding configurable thresholds (default 200,000 documents). Type checking ensures range queries are only applied to numeric and date fields, preventing type mismatches that would cause runtime errors.

A particularly notable architectural decision is the implementation of a context-aware security filter that distinguishes between legitimate security analysis queries and potential attack vectors. The filter employs pattern-based detection with severity classification, examining queries for SQL injection patterns, command injection attempts, destructive operations, and attempts to bypass validation rules. The system implements retry logic with progressively enhanced prompts when initial generation attempts fail validation, demonstrating an adaptive approach to query refinement.

The framework supports both local LLM deployment through Ollama and integration with external LLM providers including OpenAI (GPT-4o, o1, o3-mini), Google Gemini (2.5-Pro, 2.5-Flash), DeepSeek (Reasoner, Chat, Coder), and Qwen (Max, Plus, Turbo) APIs. This multi-provider approach enables hybrid deployment strategies where organizations can balance data privacy requirements, cost considerations, and accuracy demands. The system intelligently routes queries to appropriate models based on complexity, with local models handling routine queries and advanced cloud models addressing sophisticated analytical challenges.

3. TESTING AND VALIDATION STRATEGIES

The evaluation framework represents a cornerstone of the system's design philosophy, implementing multiple complementary assessment methodologies. Structural validation employs Abstract Syntax Tree (AST) normalization to compare generated queries against ground truth, computing clause-level F1 scores that measure semantic similarity independent of syntactic variations. This approach recognizes that multiple syntactically different queries can be semantically equivalent, focusing on the logical structure rather than surface-level differences.

Execution-based evaluation goes beyond structural comparison by actually executing queries against populated Elasticsearch indices and comparing retrieved document sets. The system computes precision, recall, F1 scores, and Jaccard similarity coefficients between result sets, providing empirical evidence of retrieval effectiveness. This dual approach—combining structural and execution-based metrics—ensures both query correctness and practical effectiveness.

The testing infrastructure includes 12 predefined scenarios covering common security analysis patterns plus specialized CIC-IDS2017 attack scenarios encompassing DDoS, web attacks, infiltration, and botnet detection. Each scenario includes expert-crafted ground truth queries that serve as gold standards for evaluation. The enhanced evaluation framework supports cross-dataset validation, enabling researchers to assess model performance across both synthetic and real-world attack patterns. The system also supports adversarial testing through a red team module that systematically probes for security vulnerabilities using prompt injection, ambiguous queries, and malformed inputs across multiple model types.

Continuous integration testing is facilitated through automated test suites that verify component functionality, end-to-end query generation pipelines, and system integration points. The framework generates detailed evaluation reports with timestamped results, enabling longitudinal performance tracking and regression detection.

4. STRENGTHS AND LIMITATIONS

The system demonstrates several notable strengths. The multi-layered validation architecture provides defense-in-depth against both accidental misuse and deliberate attacks, with sophisticated pattern recognition that distinguishes between legitimate security analysis and malicious attempts. The support for multiple generation methodologies and diverse LLM providers allows graceful degradation and intelligent model selection based on query characteristics. The comprehensive evaluation framework enables quantitative assessment of system performance across diverse query types, datasets, and model architectures. The modular architecture facilitates component-level improvements without requiring system-wide modifications, enabling rapid integration of new LLM providers and evaluation methodologies.

Integration with real-world datasets (CIC-IDS2017) demonstrates practical applicability beyond synthetic test cases. The system handles complex temporal expressions, converting relative time references ("last week", "yesterday") into absolute date ranges required by Elasticsearch. The implementation of differential privacy mechanisms and privacy-preserving indices shows consideration for data protection requirements in sensitive environments.

However, several limitations must be acknowledged. The system's effectiveness is inherently bounded by the quality and capabilities of the underlying language models, though the multi-provider approach mitigates reliance on any single model architecture. Complex aggregation queries and multi-stage analytical pipelines remain challenging to express through natural language, requiring domain expertise to craft effective prompts. The validation rules, while comprehensive, may occasionally reject legitimate but unusual query patterns, necessitating ongoing refinement based on operational feedback. The current implementation focuses on read-only queries, excluding data modification operations by design for security reasons. External LLM dependencies introduce cost considerations and potential service availability constraints, though local model fallbacks provide resilience.

5. RESULTS AND PRACTICAL IMPACT

Empirical evaluation demonstrates strong performance across both standard benchmarks and real-world datasets. The enhanced constrained generation approach achieves average F1 scores exceeding 0.85 on structural similarity and 0.80 on execution-based metrics across evaluation scenarios, representing significant improvements over earlier implementations. The system successfully blocks 95% of adversarial prompts while maintaining a false positive rate below 3% for legitimate queries, demonstrating robust security filtering. Cross-model evaluation reveals performance variations, with advanced cloud models achieving marginally higher accuracy at increased cost, while local models provide competitive results with complete data privacy. Query generation typically completes within 2-5 seconds for local models and 1-3 seconds for cloud-based models, with intelligent caching reducing repeated query latency.

The practical impact extends beyond raw performance metrics. By lowering the technical barrier to log analysis, the system enables junior analysts to perform investigations previously requiring senior expertise. The enforced security constraints prevent accidental data exposure or system disruption, critical in production environments. The standardization of query patterns through validated generation promotes consistency across analytical workflows.

The framework has implications for security operations center (SOC) efficiency, potentially reducing mean time to detection (MTTD) and mean time to response (MTTR) for security incidents. The ability to rapidly prototype and refine queries through natural language iteration accelerates hypothesis testing during incident response, while the multi-model approach allows teams to leverage the most appropriate AI capabilities for different analytical tasks. The web-based interface democratizes access to advanced query generation capabilities, enabling distributed teams to collaborate effectively. The comprehensive audit trail of generated queries supports compliance requirements and forensic review, with detailed model attribution and validation logs.

6. CONCLUSION

ES-NL2DSL represents a mature implementation of natural language to DSL translation specifically optimized for cybersecurity applications. The system successfully balances usability, security, and performance through a carefully architected pipeline that combines diverse LLM capabilities with sophisticated validation techniques. The comprehensive evaluation framework, support for real-world datasets, and multi-provider model integration demonstrate commitment to empirical validation, practical applicability, and technological adaptability.

The project exemplifies best practices in secure system design, implementing defense-in-depth strategies, comprehensive testing methodologies, and careful consideration of failure modes across multiple model architectures. The hybrid local-cloud approach addresses varying organizational requirements for data privacy, cost control, and analytical capability. While limitations exist, particularly around complex analytical queries and the inherent challenges of natural language ambiguity, the system provides significant value in democratizing access to powerful log analysis capabilities while maintaining operational and security constraints essential for production deployment.

The framework's modular architecture and comprehensive evaluation infrastructure position it well for future enhancements, including integration with emerging LLM technologies, expanded dataset support, and enhanced reasoning capabilities. The multi-provider approach ensures resilience against technological obsolescence and enables continuous optimization as AI capabilities evolve. This foundation supports the system's evolution from a research prototype to a production-ready tool that bridges the gap between human intuition and machine-executable analytical queries in cybersecurity contexts.
